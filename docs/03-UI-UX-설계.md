# 03. UI / UX 설계 (모바일 기반)

## 1. 설계 원칙 (프론트엔드 수석 + 디자이너 관점)

1. **엄지 하나로 끝난다 (One-thumb)** — 경기 중엔 폰을 한 손으로 든다. 주요 액션은 화면 하단·중앙, 버튼은 최소 44pt.
2. **탭은 결과가 즉시 보인다** — 탭하면 카운트 숫자가 그 자리에서 바뀌고 진동(햅틱) 피드백. "됐나?" 불안 제거.
3. **색은 정보일 때만 쓴다** — 긍정(성공)=세이지, 부정(실패/파울)=테라코타. 나머지는 무채색. 색이 남발되면 경기 중 판단이 느려진다.
4. **파스텔 · 저채도** — 경기장 야외 밝은 환경 + 장시간 사용. 쨍한 색은 눈을 피로하게 하므로 채도를 낮춘 웜 톤으로.
5. **정보는 한 화면에** — 기록 화면은 스크롤을 최소화해 그리드로 한눈에. 리포트는 "레이더 → 근거 → 통계" 순으로 위에서 아래로 읽힌다.

## 2. 디자인 토큰 (파스텔 시스템)

`app/assets/style.css`의 `:root`에 정의. 원본 기획서의 골드 아이덴티티는 유지하되 **채도를 크게 낮춰** 파스텔화했습니다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#f6f5f1` | 웜 페이퍼 배경 |
| `--card` | `#ffffff` | 카드 |
| `--ink` | `#3a3c42` | 본문 (순검정 대신 소프트 차콜) |
| `--ink-2` | `#8b8e95` | 보조 텍스트 |
| `--gold` | `#b6a279` | 파스텔 샌드 (아바타/차트 필) |
| `--gold-cta` | `#9c885a` | 솔리드 버튼 (흰 글씨 대비 확보) |
| `--gold-ink` | `#8a7846` | 텍스트/스코어 액센트 |
| `--ok` | `#7ba889` | 뮤트 세이지 (성공) |
| `--bad` | `#cf9990` | 뮤트 테라코타 (실패/경고) |

> **접근성 메모**: 파스텔이라도 "흰 글씨가 올라가는 솔리드 버튼"은 대비가 필요하므로,
> 필(fill)용 밝은 톤(`--gold`)과 컨트롤/텍스트용 약간 진한 톤(`--gold-cta`, `--gold-ink`)을 **분리**했습니다.
> 이게 "파스텔이면서도 읽히는" 디자인의 핵심 트릭입니다.

## 3. 핵심 화면별 UX 결정

### ⓐ 기록 화면 (screenRecord) — 앱의 심장
- 상단에 **선수 칩 스트립**(가로 스크롤) → 여러 선수를 탭 한 번으로 전환하며 기록.
- 이벤트를 **공격 / 패스·드리블 / 수비·활동량 / 기타** 4그룹, 3열 그리드로 배치 → 시선 이동 최소화.
- 각 버튼: 큰 라벨 + 큰 숫자. 우상단에 작은 `−` (오입력 복구). 탭 시 `scale(.94)` + 진동.
- 하단 고정 CTA: `정성 평가 →` / `경기 종료`. 종료 전까지 상단에 **● 기록중** 배지.

### ⓑ 선수 리포트 (screenReport) — 결론을 보여주는 화면
- 최상단: 아바타 + **종합 가치 점수 배지**(5 KPI 평균). "이 선수 몇 점"에 즉답.
- 중앙: **오각형 레이더**(기획서와 동일한 축 순서). 파스텔 골드 필 + 저채도 그리드.
- 레이더 아래: KPI별 **계산 근거**(하위 지표 값 + Z score) → 점수가 어떻게 나왔는지 투명 공개 = 신뢰.
- 하단: 시즌 누적 기록 2열 카드.

### ⓒ 하단 탭바
- 이모지 대신 **단색 라인 아이콘**(선수/경기/리포트)으로 통일 → 팔레트와 충돌하는 원색 제거.

## 4. 프론트엔드 수석 관점의 개선 포인트 (이번 반영분)

- ✅ 레이더 축 라벨이 잘리던 문제 → viewBox 폭 확대 + 반응형 `width:100%`로 해결.
- ✅ 원색 이모지 탭 아이콘 → `currentColor` 기반 인라인 SVG로 교체(채도 제거, 라이트/다크 확장 용이).
- ✅ 색 토큰을 필/컨트롤/텍스트로 3분할 → 파스텔 유지하면서 대비 확보.
- ✅ 탭 그리드에 성공/실패 미묘한 배경 그라데이션 → 색을 진하게 쓰지 않고도 긍정/부정 구분.

## 5. 다음 UI 단계 (프로덕션 전환 시)

- 컴포넌트화(React/Next)로 옮기되 **토큰·레이아웃은 그대로 이식**.
- 다크 모드: 토큰만 교체하면 되도록 이미 CSS 변수화 완료.
- 기록 화면 커스텀: 포지션별로 자주 쓰는 버튼만 노출하는 프리셋.
